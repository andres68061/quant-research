# Data Health

**What this is:** the living record of the state of our data — what we hold, how
complete it is, and every known flaw a result could silently inherit. The chat
where a flaw was discovered scrolls away; this document does not.

**Where every record lives:** see [docs/README.md](../README.md). Short version —
caveats in `core/research/caveats.py`, measured flaws in
`core/data/quality/health.py::known_flaws`, decisions in `decisions/`, negative results
in `FAILED_STRATEGIES_LOG.md`, plans in `ROADMAP.md`. Nothing is written twice.

Three sections below:

1. **Prose caveats** (this section) — standing context, written by hand.
2. **Registry caveats** — the shared disclosures, defined once in
   `core/research/caveats.py` and rendered identically here, on `/data-health`,
   on the sector page, and on the PEAD page. A surface cannot omit one.
3. **The generated section** — numbers recomputed from disk by
   `scripts/ops/audit_data_health.py`. Never edit it; rerun the script.

**The enforcement rule** (in the `data-inventory-sync` and `research-disclosure`
skills): any session that adds/reshapes a data artifact must rerun
`scripts/ops/audit_data_health.py` before it ends; any session that adds a surface
showing research numbers must register its caveats. A fixed flaw is *removed*
from the registry and, if methodologically interesting, memorialized as an ADR.

## How to read a severity

- **high** — can silently flip a research conclusion (leakage, unadjusted
  prices, cost assumptions that flatter a strategy). Do not act on affected
  results without applying the stated remediation.
- **medium** — biases a known subset (an era, a size band, a factor family).
  State the caveat alongside any result touching that subset.
- **low** — operational; will not corrupt a result but will confuse a session
  that does not know about it.

## Standing context that is not a "flaw"

- **Point-in-time discipline lives in three places:** the
  `reference_date`/`publication_date`/`as_of_date` vocabulary (CLAUDE.md), the
  per-dataset `pit_status` labels in `core/data/vendors/fmp/datasets.py` (ADR 0010), and
  the per-row `publication_date_imputed` flag in the fundamentals panel
  (ADR 0012). New data must plug into all three, not invent a fourth.
- **The canonical universe is now the full US market** (ADR 0013, 2026-08-12):
  ~8,900 symbols, live + delisted. Index membership became a *label*
  (`data/universe/index_membership.parquet`), not a universe — S&P-restricted
  research filters on membership intervals rather than on which file it loaded.
  The old 774-name S&P union panel is archived under `data/factors/archive/`
  and remains the reproduction reference for any pre-cutover result.
- **Vendor scores are reconciliation targets, not inputs.** Our Piotroski
  differs from FMP's per-name (TTM-quarterly vs annual — ADR 0011); Altman Z
  reconciles at corr 0.98. Neither vendor snapshot is backtestable.

### Known flaws (machine-readable registry)

| Severity | Flaw | Detail |
|---|---|---|
| **medium** | Old delistings are under-covered | 93 delisted names have no price history, concentrated in pre-2015 delistings (e.g. Compaq, Countrywide, Albertsons). FMP's delisted feed skews recent — backtests before ~2015 on the expanded universe still lean toward survivors. The 774-name S&P membership panel is the better pre-2015 universe. |
| **high** | 26.2% of statement rows had placeholder filing dates | FMP fills acceptedDate with the period end for pre-EDGAR filings (100% of 1980s rows, ~50% of 1990s). Taken literally this made results knowable the day the quarter closed. Remediated with a 45-day fallback lag, flagged per-row as publication_date_imputed (ADR 0012). Results leaning on pre-2000 history must be re-run excluding imputed rows. |
| **medium** | Raw event datasets cover 6,764 symbols, but the DERIVED surprise/vendor panels are still 774-name builds | The expanded dataset fetch completed (earnings, ratios, etc. now cover most of the universe), but factors_earnings_surprise.parquet and factors_vendor_metrics.parquet are built against the canonical 774-name price panel. PEAD and vendor-metric research is large-cap-only until build_event_factors gains an --expanded mode against prices_fmp.parquet — which matters, because the PEAD literature puts the effect in small caps. |
| **high** | Intraday: frozen split-adjustment snapshot, no dividend adjustment, bar-capped endpoint | (1) Stored intraday bars are split-adjusted AS OF THE FETCH DATE (measured on AAPL/NVDA/TSLA splits, 2026-08-11) — a split after the fetch leaves them stale, and a blanket re-adjustment double-adjusts. Always read via core.data.vendors.fmp.intraday.load_intraday_bars, which detects and repairs exactly the unapplied splits. (2) Bars are NEVER dividend-adjusted, unlike the daily adj_close layer: overnight returns across ex-dividend dates carry the dividend drop as a fake negative return. (3) The endpoint silently returns only the most recent ~1,170 bars per request; only the chunked fetcher is safe. |
| **low** | Canonical prices.parquet is still the 774-name panel | The expanded 8,908-symbol panel lives in prices_fmp.parquet (staging). The API, existing backtests, and the fundamentals build still run on the 774 panel. Cutover is a deliberate pending decision (memory, calendar, and every downstream artifact change with it). |
| **medium** | Sector labels are today's, applied historically | FMP exposes only current sector/industry. Sector-neutral factors (value_quality_sn, roe_sn) carry mild lookahead through reclassifications (documented in core/signals/sector_neutral.py). |
| **high** | Vendor bad prints produce daily returns up to +100,000,000% | Un-adjusted reverse splits and quote errors on delisted micro-caps. Measured 2026-08-13: max daily return +101,599,900%; 7,691 returns above +100%; 20,642 exact-zero closes (now nulled by the panel builder). One such value in a cross-sectional mean makes every symbol's abnormal return infinite for that date. All return math must go through core.data.returns.compute_clean_returns. |
| **high** | 20% of the universe is shell companies / SPACs, not operating businesses | 1,779 of ~9,000 symbols carry industry 'Shell Companies' (measured 2026-08-12) — pre-merger SPACs and blank-check vehicles. A pre-merger SPAC is a trust account with a ticker: it sits within pennies of $10.00 (many show annualized vol under 5%), then merges into an unrelated business or liquidates. Ranking one on momentum, value or profitability is meaningless, and its near-zero volatility makes it look like an extreme low-vol name, so it lands in traded tiers rather than the middle. Use core.data.universe_filters.build_universe_filter(exclude_non_operating=True) for any cross-sectional work on the expanded universe. |

Fix on the next universe rebuild: add a REIT-inclusive pass (sector=Real Estate, isEtf=false) and audit exchange coverage. |
