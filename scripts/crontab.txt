# Quant platform — scheduled data updates and monitoring
# Restore with: crontab scripts/crontab.txt
#
# Update jobs run daily at 6 PM (after US market close).
# The watchdog runs several times a day, because the failure it exists to catch
# is a job that STOPS running — which produces no error and no log line.
# Logs land in <repo>/logs/<job>.log.
#
# Python interpreter: conda env "quant"
# Repo root:         /Users/andres/Downloads/Cursor/quant

# 1. Prices, macro (FRED), Fama-French 5, price factors, sectors (quarterly auto-refresh)
0 18 * * * cd /Users/andres/Downloads/Cursor/quant && /opt/anaconda3/envs/quant/bin/python scripts/update_daily.py >> logs/update.log 2>&1

# 2. Commodity prices (GLD, SLV, WTI, etc.)
5 18 * * * cd /Users/andres/Downloads/Cursor/quant && /opt/anaconda3/envs/quant/bin/python scripts/update_commodities.py >> logs/commodities_update.log 2>&1

# 3. Shares outstanding + historical market caps (yfinance, free)
10 18 * * * cd /Users/andres/Downloads/Cursor/quant && /opt/anaconda3/envs/quant/bin/python scripts/fetch_shares_and_market_caps.py >> logs/market_caps_update.log 2>&1

# 4. Watchdog — fast checks (panels present, not collapsed, jobs still firing).
#    Every 4 hours. Cheap: parquet footers and file mtimes only, no data scan.
#    On error it fires a macOS notification and the app shows a banner.
0 */4 * * * cd /Users/andres/Downloads/Cursor/quant && /opt/anaconda3/envs/quant/bin/python scripts/run_watchdog.py >> logs/watchdog.log 2>&1

# 5. Watchdog — deep check (scans panel values for structural violations).
#    Once daily at 6:40 PM, i.e. AFTER the update jobs above have landed, so it
#    validates what they just wrote rather than yesterday's artifacts.
40 18 * * * cd /Users/andres/Downloads/Cursor/quant && /opt/anaconda3/envs/quant/bin/python scripts/run_watchdog.py --deep >> logs/watchdog.log 2>&1

# 6. FMP vendor ingestion — NOT ENABLED. Uncomment only after reading
#    docs/INGESTION.md; wave 2 is a multi-hour, several-hundred-thousand-call job.
#
#    Both jobs are safe to re-run: completion is a file on disk, so a repeat run
#    skips what already landed and costs zero API calls for it. Outcomes go to the
#    SQLite journal at data/quality/ingest_journal.db; a text report per run lands
#    in data/quality/ingest_reports/.
#
#    The two jobs MUST NOT overlap. The rate limiter lives inside one process, so
#    two concurrent ingesters emit twice the configured calls/minute and risk the
#    vendor throttling the key. The times below are chosen so a cold wave-2 run
#    (Sunday 02:00, ~12.3 h) finishes hours before Sunday's 18:20 wave-1 job.
#    Run scripts/validate_fmp_manifest.py before enabling either one: it costs a
#    few hundred calls and catches specs that silently return zero rows.
#
#    Why wave 1 is NIGHTLY: it is the global reference layer — symbol and CIK
#    directories, index constituents, delisted names, symbol changes, and the
#    earnings/dividends/splits/IPO/economic calendars. Every one of those changes
#    daily, and a stale calendar silently mis-dates an event study. It is also
#    cheap: 66 tasks, measured at ~5 minutes wall clock. Runs at 6:20 PM, after
#    the 6:00-6:10 PM update jobs and before the 6:40 PM deep watchdog.
#
#    Why wave 2 is WEEKLY: it is the per-symbol history layer — statements,
#    ratios, key metrics, earnings, dividends, splits, grades, insider trades.
#    441,539 tasks, ~12.3 hours estimated at 600 calls/min for a cold run. The
#    underlying data only changes when a company files, which for any one symbol
#    is roughly quarterly, so a nightly re-pull would spend hours re-confirming
#    unchanged rows. Weekly is already faster than the filing cadence. It runs
#    Sunday 02:00 so the long tail finishes well before Monday's market open, and
#    --force is deliberately ABSENT: without it the run only fetches what is
#    missing, which after the first pass is a few thousand tasks, not 441,539.
#    Add --force only to deliberately refetch after a vendor restatement, and
#    narrow it with --endpoints when you do.
#
# 20 18 * * * cd /Users/andres/Downloads/Cursor/quant && /opt/anaconda3/envs/quant/bin/python scripts/ingest_fmp.py --wave 1 >> logs/ingest_wave1.log 2>&1
# 0 2 * * 0 cd /Users/andres/Downloads/Cursor/quant && /opt/anaconda3/envs/quant/bin/python scripts/ingest_fmp.py --wave 2 >> logs/ingest_wave2.log 2>&1
